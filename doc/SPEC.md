# QMap 仕様書

QMap は LLM との対話を Git のコミットツリーのように分岐・可視化する Web サービス。ユーザー自身の LLM API キーを使い、QMap 側のコストを最小化しつつ、複雑な学習・調査を枝分かれさせて比較できる。

## 目的 / 価値
- 過去ノードから何度でも「別の未来」を試し、回答を比較できる。
- 話題単位でツリーを整理し、分岐を俯瞰しながら学習・調査を進められる。
- QMap は LLM 代を負担せず、運用コストを極小化する。

## 主要ペルソナとユースケース（抜粋）
- 技術リサーチャー: 設計案を複数分岐で比較する。
- 学習者: 学び直しポイントを「あとで聞く」ノードで残し、後日深掘りする。
- ライター: 構成案を分岐させながら最適案を見つける。

## 画面構成（3 カラム）
- 左ペイン: スレッド一覧（Topic List）
  - Topic 名を一覧表示。選択で中央ペインのツリーを切替。
  - 「新規スレッド作成」でルートノードを生成。
- 中央ペイン: ノードマップ（Tree View）
  - 縦方向を時系列、横方向インデントで分岐を表現。
  - parentId から depth を算出しインデントを決定。
  - ノード表示: 左に線 + 丸ノード（番号）、右にタイトル。ホバーで summary をツールチップ表示。
- 右ペイン: 会話ログ + チャット
  - 選択ノードまでのパス表示（例: A1 → B1 → C2）。
  - パス内ノードの messages を順に表示（user / assistant）。
  - 入力フォーム + 送信ボタン、別途「あとで聞くノードを追加」ボタン。

## コア概念とデータモデル
- Topic
  ```ts
  type Topic = { id: string; name: string };
  ```
- Node
  ```ts
  type Node = {
    id: string;              // ULID（内部 ID）
    label: string;           // UI 表示用ラベル（例: A1, B2）
    title: string;           // ノード表示名
    summary: string;         // 質問または要約（ホバー表示）
    parentId: string | null; // ルートは null
    messages?: ChatMessage[]; // 会話ログ（user/assistant）を保持する実装を許容（v1 は単ターン）
  };
  ```
- UserSettings
  ```ts
  type UserSettings = {
    llmProvider: "openai" | "anthropic" | "gemini" | "openrouter" | "local";
    apiKey: string; // KMS で暗号化保存
    model: string;
  };
  ```
- ChatMessage は role (`user` | `assistant`) と content の配列を想定。

## ノード生成・分岐ルール
- チャット送信時
  - 基点ノードが通常ノードの場合: parentId=基点ノード.id で子ノードを新規生成し、送信/応答を messages に保存。
  - 基点ノードが「あとで聞く」ノードの場合: そのノードを再利用して chat に昇格（label/parentId は維持）。title/summary を下書き内容で置換し、messages は今回の user/assistant 2 件のみで上書きする。新規ノードは作成しない。
- 「あとで聞く」ノード
  - チャット送信とは独立したボタン操作。
  - LLM へは問い合わせず、入力テキストを summary としたノードを基点ノード直下に作成。
  - messages は空（タグ／質問候補として扱う）。
  - 選択時にタイトルを下書きへプリフィルし、送信するとそのノードがチャットノードに昇格する。

## LLM 連携仕様（最重要）
- 送信する履歴
  - 選択ノードまでのパスに含まれる各ノードの messages のみを LLM に渡す。
  - パス外の未来分岐（兄弟・子孫）は送信しない。
  - 切替例: C1 選択 → A1 → B1 → C1 のログだけ送信／表示。C2 選択 → A1 → B1 → C2 のログだけ。
- 送信ペイロード例（OpenAI）
  ```json
  {
    "model": "gpt-4.1",
    "messages": [
      { "role": "assistant", "content": "A1 の応答..." },
      { "role": "user", "content": "B1 の質問..." },
      { "role": "assistant", "content": "B1 の回答..." },
      { "role": "user", "content": "C2 の質問..." }
    ]
  }
  ```
- LLM は stateless 前提。毎回 QMap が正しいパスの messages を構築して送信する。
- ユーザー設定
  - 設定画面でプロバイダ / API キー / モデル名を登録。
  - 推奨保存: DynamoDB に暗号化（AWS KMS）し、Lambda 呼出時に復号して利用。
  - QMap は LLM 料金を負担しない（ユーザー負担）。

## 代表的なユーザーフロー
- Topic 作成: Topic 名入力 → ルートノードを自動生成 → 中央ペインに表示。
- ノード選択: Tree View で任意ノードを選ぶ → 右ペインに当該パスのログを表示。
- チャット送信: 右ペインで入力 → 基点ノード直下に新ノード生成 → パス＋messages を LLM へ送信し応答保存。
- 未来分岐: 過去ノードを選択して送信/「あとで聞く」で新規子ノードを作成し別の未来を形成。
- まとめビュー: Topic 単位でノード・分岐・獲得知識を LLM に要約させ表示。

## UI 仕様補足
- ノード表示
  - 左側に縦線と丸ノード（番号表示）。右側にタイトル（短い説明）。
  - ホバーで summary のツールチップ。
  - 深さに応じて横インデントを付与。
- パス表示: 右ペインの冒頭に「A1 → B1 → C2」形式で現在の履歴を表示。
- 並び: 同一深さ内では生成時刻（タイムライン順）で上から下へ表示。
- 入力ショートカット: チャット入力で Ctrl+Enter（Mac は Cmd+Enter）送信をサポート。

## 非機能・運用
- コスト試算（ユーザー LLM 代除外）
  - Vercel Hosting: 100〜400 円/月 規模
  - DynamoDB: 0〜100 円/月
  - Lambda: 10〜50 円/月
  - CloudWatch: 50〜100 円/月
  - 合計目安: 200〜650 円/月（100 ユーザー規模でもほぼ一定）。
- セキュリティ
  - API キーは KMS 暗号化で保存し、復号は実行時限定。
  - LLM 送信データは選択パスのみ。不要な履歴・未来分岐は送らない。

## LLM API キー入力・保存
- 入力場所: ヘッダー/設定アイコンから遷移する「ユーザー設定」画面にフォームを用意。
- 操作: プロバイダ選択（OpenAI/Anthropic/Gemini/OpenRouter/Local）+ モデル名 + API キーを入力し保存。
- 送信: `POST /me/settings` に平文キーを送信（TLS 前提）。Lambda 側で KMS 暗号化保存し、レスポンスは `apiKeyMasked` のみ。
- 取得: `GET /me/settings` でマスク済み値とプロバイダ/モデルを表示。未設定なら null。
- 利用: `/chat` などの LLM 呼び出し時に Lambda が KMS で復号して使用。クライアントに平文キーを返さない。

## 成功判定のチェックリスト
- 任意ノードから分岐でき、パス外の履歴を LLM に送らない。
- 「あとで聞く」ノードが LLM コールなしで追加できる。
- パスの会話ログ表示が選択ノードごとに正しく切替わる。
- Topic 単位でツリーを複数管理できる。
- まとめビューで Topic の学びと分岐を要約できる。
