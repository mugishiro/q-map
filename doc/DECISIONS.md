# QMap v1 決定事項（初期ポリシー）

将来変更しやすいように、現時点でのデフォルトを明文化する。

2025-01-XX 更新: 「あとで聞く」ノードは `/chat` で `nodeId` を指定しチャットに昇格（label/parentId 維持、messages は送信/応答の 2 件で上書き）。フロントは Ctrl/Cmd+Enter 送信をサポート。

## ID と表示
- Node ID: 内部 ID は ULID（衝突回避とソート性）。Topic 間で一意。
- ラベル: ユーザー向けの見た目ラベルは別フィールド `label`（例: A1/B2/C3）を持つ。表示・コピー用で、内部参照には ULID を使う。

## メッセージ保持
- v1 はノード内 messages を「1ターン固定（user→assistant の往復1回）」にする。
- 履歴はルート→選択ノードのパスで連結して再現する前提。
- 将来 multi-turn を許可する場合は `messages` 配列をそのまま増やすだけで互換性を保つ。

## トークン削減方針
- v1 は「何もしない」で開始（パスをそのまま LLM に送る）。
- 閾値が見えてきたら summary ノード導入を検討するルール案:
  - 例: パスが 40 メッセージ超 or 16k tokens 超で古い区間を要約ノードに置き換え/併設。
  - 実装は後回し。先に計測基盤だけ用意（リクエスト時に token 見積もりログを取る）。

## URL / ルーティング
- REST:
  - `/topics` 一覧/作成
  - `/topics/:topicId` メタ情報
  - `/topics/:topicId/nodes` ノード一覧（includeMessages 任意）
  - `/nodes/:nodeId` ノード詳細
  - `/nodes/:nodeId/path` パス取得
  - `/chat` 新規チャットノード作成（baseNodeId 付き）
- フロントルーティング:
  - `/topics/:topicId/nodes/:nodeId` を基本とし、直接ブックマーク可能にする。

## LLM 設定
- ユーザーごとにアクティブ設定は 1 件のみ。`POST /me/settings` は上書き保存（複数プロファイル未対応、将来検討）。

## ラベル付与ルール
- 内部 ID は ULID。表示用の `label` は深さごとに生成順で付与（例: ルートは A1、同階層の次ノードは B1、子ノードは親に対して 1 ずつ増やす等、詳細実装は後続で固定）。リネームは `PATCH /nodes/{id}` で title/summary のみ変更、label/ULID は不変。

## 認証方針
- v1 は Cognito Hosted UI（メール+パスワード）でサインアップ/ログイン。ソーシャルログインは未対応（将来検討）。
  - 理由: まず機能実装を優先し、IdP 設定や同意画面/規約まわりの複雑さを避ける。PII を最小化し、メール+パスワードのみで開始。
